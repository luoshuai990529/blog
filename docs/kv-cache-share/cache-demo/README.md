# 缓存实验回放

线上演讲稿只读取结果，不执行 Python，也不请求模型 API。

## 采集并导出

下载 collect_replay.py，用 Python 3 运行：

    python3 collect_replay.py --output results.json

在本地终端隐藏输入密钥。脚本发送 2 次预热和 10 次测量请求，产生 API 费用；不保存密钥、提示词正文或模型回答。失败样本仍保留，不能只选速度好看的样本。

演讲页点击“载入结果”可在当前浏览器预览 JSON，此操作不上传也不会更新线上部署。

要让所有线上访客看到结果，将 results.json 放到工程 public/cache-demo/results.json，再重新构建和部署。初始文件 null 表示尚无实测，不是零值实验。

## 实验方法

稳定组使用本次运行唯一但组内相同的首行标记；改首前缀组逐次使用随机标记。其余系统文本、任务、模型和参数相同。两组各 5 次测量，交替运行并逐对交换顺序，预热不计入汇总。

TTFT 从发起请求前计时，到首个非空 content 增量到达为止；包括网络与服务端等待。命中率用 API 返回的 prompt_cache_hit_tokens / prompt_tokens，不能只靠 TTFT 判断缓存命中。随机标记不保证实际首个 token 一定不同，是否命中以 usage 为准。

回放按固定节奏揭示记录，不模拟原始耗时。未命中组有时也可能更快，不强制宣称加速倍数。此处演示 API Prompt Cache 对计算结果的跨请求复用。

原始 notebook 可单独下载复现原实验；采集脚本沿用其构造与计时方法，增加结构化结果导出、交错顺序及失败处理。
