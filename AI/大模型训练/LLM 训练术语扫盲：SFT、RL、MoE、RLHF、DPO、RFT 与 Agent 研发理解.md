# LLM 训练术语扫盲：SFT、RL、MoE、RLHF、DPO、RFT 与 Agent 研发理解

## 一、为什么 Agent 研发者需要理解这些训练术语

Agent 应用开发不一定需要自己训练大模型，但训练方式会影响模型是否听得懂指令、是否愿意调用工具、是否能进行多步推理、是否容易产生幻觉、是否适合低成本部署。

理解这些术语不是为了转型做算法研究，而是为了判断：模型的能力从哪里来，遇到问题应该优化 Prompt、RAG、Agent 流程，还是需要换模型或做微调。

## 二、先建立一张整体地图

~~~
预训练：让模型获得语言、知识和基础模式
  ↓
SFT：教模型遵循指令和示范格式
  ↓
偏好优化 / 强化学习：教模型什么答案更好
  ↓
Agent 训练：教模型在工具和环境中完成多步任务
  ↓
蒸馏：把大模型能力迁移到更小模型
  ↓
部署：在成本、延迟和稳定性之间取舍
~~~

MoE 不是训练阶段，而是一种模型架构；RLHF、DPO、RFT、GRPO 都属于后训练或偏好优化相关方法。

## 三、预训练：给模型打基础

预训练（Pretraining）通常通过大量文本进行下一个 token 预测，让模型学习语言分布、知识和表达规律。

预训练主要解决：

- 模型知道什么。
- 模型能理解哪些语言和表达。
- 模型具备什么基础泛化能力。

预训练没有解决：

- 是否遵循用户指令。
- 是否按指定格式输出。
- 是否安全拒答。
- 是否稳定调用工具。

对 Agent 研发的理解是：预训练决定模型的能力上限，但不能保证模型直接成为好用的 Agent。

## 四、SFT：监督微调

SFT 是 Supervised Fine-Tuning，即监督微调。它使用“指令—回答”样本继续训练模型：

~~~
用户：查询订单状态
助手：请提供订单号，我会帮你查询。
~~~

SFT 主要教模型理解指令、组织回答、遵守格式、表现出助手风格以及按照示范调用工具。

对 Agent 的实际意义：

- 可以让模型学会固定的工具调用格式。
- 可以让模型更适合企业内部任务。
- 可以让模型形成领域术语和输出风格。

SFT 更像“示范教学”，不一定能让模型学会复杂探索、失败恢复和长期规划。

## 五、RL：强化学习

RL 是 Reinforcement Learning，即强化学习。

它不是直接告诉模型正确答案，而是让模型尝试多个行为，根据结果获得奖励或惩罚，再逐渐提高高奖励行为的概率。

~~~
模型采取行动
  → 环境返回结果
  → Reward 给出奖励
  → 模型调整策略
~~~

在 Agent 中，行动可能是选择哪个工具、先检索还是先追问、是否拆分任务、是否并行调用子 Agent，以及什么时候结束任务。

强化学习适合结果可验证的数学、代码、逻辑和工具执行任务。

## 六、RLHF：基于人类反馈的强化学习

RLHF 是 Reinforcement Learning from Human Feedback，即基于人类反馈的强化学习。

它通常包含：

~~~
收集高质量示范
  → 收集人类偏好比较
  → 训练奖励模型并进行强化学习
~~~

RLHF 主要改善指令遵循、回答风格、有用性、拒答行为和安全边界。

难点是人类标注成本高，而且人类偏好并不总是等于真实质量。回答更长、更有礼貌，不一定代表更准确。

## 七、DPO：直接偏好优化

DPO 是 Direct Preference Optimization，即直接偏好优化。

它使用同一个问题下的好回答和差回答，直接提高好回答的概率，降低差回答的概率，不需要单独训练奖励模型。

~~~
RLHF：先训练奖励模型，再做强化学习
DPO：直接使用偏好对训练模型
~~~

如果有大量“正确回答 vs 错误回答”的数据，可以考虑偏好微调；如果只是希望模型遵循项目规则，通常先用 Prompt、工具约束和 RAG，不必直接做 DPO。

## 八、RFT：强化微调

RFT 是 Reinforcement Fine-Tuning，即强化微调。

它更强调工程化地定义任务、正确结果、Grader 和 Reward：

~~~
定义任务
  → Agent 执行
  → Grader 评分
  → Reward 优化
  → 继续训练
~~~

RFT 适合数学题自动判分、代码测试、SQL 执行结果验证、工具调用验证和结构化输出校验。

对 Agent 研发最重要的理解是：RFT 的关键不只是训练算法，而是能否设计可靠的任务、环境和验证器。

## 九、GRPO：组内相对比较的强化学习方法

GRPO 是 Group Relative Policy Optimization。

它针对同一个问题采样多个回答，在组内比较相对质量，不需要额外维护独立的价值网络。

~~~
同一个问题
  → 采样多个回答
  → 通过规则或 Grader 排序
  → 鼓励表现更好的回答
~~~

它适合数学、代码和逻辑任务。前提是任务可以稳定生成多个候选，并且可以可靠比较质量。

## 十、MoE：混合专家模型

MoE 是 Mixture of Experts，即混合专家模型。

它把模型拆成多个专家网络，每个 token 不需要激活全部专家，而是由路由器选择部分专家处理。

MoE 的优点：

- 总参数量可以很大。
- 每个 token 的实际计算量相对可控。
- 不同专家可能形成不同能力分工。

MoE 的代价：

- 路由和负载均衡更复杂。
- 专家之间通信成本更高。
- 训练和部署基础设施更复杂。
- 显存和服务调度更难。

对 Agent 研发的意义是：不要只看模型总参数，还要看激活参数、吞吐、延迟和实际推理成本。

## 十一、Grader：把结果转换成分数的评估器

Grader 负责判断一次模型输出是否符合目标，常见类型包括：

- 规则 Grader：检查格式、字段和正则规则。
- 程序 Grader：检查代码、SQL 或测试是否通过。
- 检索 Grader：检查是否命中正确文档。
- LLM-as-a-Judge：由另一个模型评价回答质量。
- 人工 Grader：由专家进行最终标注。

Grader 设计不好，模型就会学会钻评分规则的空子。对 Agent 研发而言，评估器不是训练外部的工具，而是直接决定系统优化方向的组件。

## 十二、Reward：模型被鼓励追求什么

Reward 是奖励信号，用来告诉模型某次行为好不好。

Agent 的 Reward 不应该只看最终答案，还可以包括：

- 任务是否完成。
- 工具调用是否正确。
- 是否遵守权限。
- 是否减少无效步骤。
- 是否正确使用上下文。
- 是否保留关键中间产物。
- 是否完成可验证交付。

如果 Reward 过于单一，模型可能优化表面指标而不是实际目标，这就是 Reward Hacking。

## 十三、ORM 和 PRM：结果评分与过程评分

ORM 是 Outcome Reward Model，即结果奖励模型，只评价最终结果。

PRM 是 Process Reward Model，即过程奖励模型，会评价中间步骤。

| 类型 | 评价对象 | 优点 | 代价 |
| --- | --- | --- | --- |
| ORM | 最终答案或最终状态 | 简单、便宜、容易启动 | 看不到错误过程 |
| PRM | 中间推理或行动步骤 | 反馈更密、过程更可控 | 标注和实现成本更高 |

Agent 项目通常可以先用 ORM 建立结果闭环，再对高风险或高价值流程增加过程检查。

## 十四、Rollout：Agent 在环境中执行一次任务

Rollout 可以理解为一次完整执行轨迹：

~~~
输入任务
  → 模型规划
  → 调用工具
  → 接收环境反馈
  → 继续行动
  → 输出最终结果
~~~

Agent 训练要关注整个 Rollout，包括工具调用顺序、参数正确性、失败恢复、上下文使用和任务完成成本，而不只是最终文本。

## 十五、Harness：包在模型外部的控制程序

Harness 是围绕模型组织 Prompt、工具、记忆、状态、上下文、权限、工作流和评测的控制程序。

~~~
模型 = 决策能力
Harness = 运行时、工作流、记忆和工具系统
~~~

很多 Agent 问题不一定需要重新训练模型，可能通过 Harness 解决：

- Query 改写。
- 检索和上下文裁剪。
- 工具选择。
- 多 Agent 编排。
- 失败重试。
- 会话恢复。
- 人工审批。
- 输出校验。

## 十六、这些术语如何帮助 Agent 研发决策

| 问题 | 优先考虑 |
| --- | --- |
| 模型不知道领域知识 | RAG、领域数据、Embedding，必要时微调 |
| 模型不遵循格式 | Prompt、Schema、Tool Calling、SFT |
| 模型不愿调用工具 | 工具描述、Harness、SFT 或后训练 |
| 多步任务容易中断 | 工作流、状态持久化、Agent 环境 |
| 模型总走捷径 | Grader、Reward、过程评估、未见测试集 |
| 成本和延迟太高 | 小模型、量化、MoE、蒸馏、缓存 |
| 风格不符合业务 | SFT、偏好数据、DPO 或 Prompt |
| 多 Agent 不知道奖励归谁 | 先优化 orchestrator，明确信用分配 |

## 十七、最终沉淀

这些缩写可以这样记住：

~~~
SFT：用示范教模型怎么做
RL：用奖励让模型探索怎么做得更好
RLHF：用人类偏好作为奖励来源
DPO：直接用好答案和坏答案做偏好优化
RFT：把任务、评分器和奖励组成强化微调流程
GRPO：通过同一问题的多条回答做组内比较
MoE：只激活部分专家，降低每个 token 的计算成本
Grader：把结果转成分数
Reward：告诉模型应该朝哪个方向优化
Rollout：Agent 在环境中完成一次任务的执行轨迹
Harness：管理模型、工具、上下文和工作流的运行时系统
~~~

对 Agent 应用研发者来说，最重要的不是背下所有缩写，而是理解每个术语对应哪一类工程问题：模型能力、行为对齐、任务验证、环境交互、成本优化，还是运行时治理。
