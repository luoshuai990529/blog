# BM25 的理论依据

## 背景

在当前 Agent 发展中，RAG 增强检索是企业级 Agent 中占比非常高的一个技术点。在 RAG 的完整链路中，两个重要阶段分别是：**索引构建**和**查询召回**。在这两个阶段中，需要根据业务场景和知识库规模选择合适的检索方案。例如，关键词检索通常使用基于倒排索引的 BM25 评分，向量检索则可以使用 FAISS 提供的 IVF、HNSW 等索引结构。本篇文章单独针对词法相关性评分函数 BM25 展开介绍。

## 理解 TFIDF：以 Lucene ClassicSimilarity 为例

在讨论 BM25 之前，我们先了解 TFIDF，以及 Lucene 历史上基于 TFIDF 的 `ClassicSimilarity` 评分实现。

**TFIDF** 是一种对于包含自然语言（各种文章）的文档进行一种**评分和排序的传统算法**，它曾经也是 **Lucene**（曾经 ElasticSearch 的底层）长期以来默认的文本评分标准。

简单来说，当你输入一个搜索词的时候，它会根据以下维度来计算哪些文档跟你的搜索词**相关**：

1. **词频** (Term Frequency, 简称 **TF)**：
   - 在计算时，系统会统计搜索词在文本中出现的次数（即词频）。
2. **逆文档频率** (Inverse Document Frequency, 简称 **IDF**)
   - 如果单靠**词频**来统计相关性会带来的问题：当你搜索“LangGraph的最佳时间”时，如果在多篇文档中存在大量的“的”时，就会导致所有的文档得分都非常高，这是不合理的。
   - TFIDF 就引入**逆文档平率**这个指标来评估，它的核心逻辑是：**当1 个词在文档中出现的频率越高，那么它的重要性就越低，反之亦然**。
   - 计算出 IDF 权重会和前面的词频分相乘，从而降低常见词对整体得分的干扰。
3. **长度归一化** (Norm)
   - TFIDF 还会考量**文档的篇幅长度**。
   - 举个例子：如果一个搜索词在一篇小的推文中出现两次，和它在一本几千页的书中出现两次，那么推文的主题大概率是关于这个搜索词的，而这本书的主题则未必。
   - 因此，**在相同的词频下，文档越长，相关性得分就会被相应的降低**。这也意味着在 TFIDF 的算法中，较短的字段比如标题，会获得更高的权重提升。

4. Lucene 中的 TFIDF 的**协调因子机制**
   - 当你搜索多个不同的关键词时，这个机制会**给予那些匹配了更多关键词的文档额外的奖励分数，这是为了避免那些只大量包含了同一个关键词的不相关文档分数排名过高**。



TFIDF 虽然一直表现不错，但它本质上是一种“经验主义”。

- 比如词频（TF）无上限容易被作弊：虽然内部通过将词频开平方的方式减缓得分，但是解决不了根本问题。
- 长度归一化过于绝对：没有考虑全语料的平均长度，长文档面对短文时会经常受到压制。
- 缺乏坚实的数学基础：很多计算细节，比如词频偏偏要开平方根，是早期开发者基于直觉和测试结果决定的
- 多次查询的补丁机制：为了防止单词极高的词频就击败多个不同关键词的优秀文档，不得不引入协调因子机制。

## BM25 的数学与概率学演进

BM25 的理论基础是起源于“概率排序原理”，它是通过纯粹的数学和概率学，计算出文档与查询绝对的相关概率来排序的。不过发展的过程中发现纯粹的概率模型最终推导出来的数学公式也很混乱，在后面开发者们选择了放弃纯粹的精确计算，选择了一条形状符合逻辑的近似数学曲线。而这个公式恰好包含了 TFIDF 的三个核心元素：词频、逆文档频率、长度归一化。因此，**BM25 在精神内核上是严谨的概率论，但在最终落地的公式形态上，长得很像 TFIDF 的升级版**。

Lucene（Elasticsearch 的底层）实际工程落地时所采用的具体变体公式：
$$
\text{bm25}(d) = \sum_{t \in q} \log \left( 1 + \frac{N - df_t + 0.5}{df_t + 0.5} \right) \cdot \frac{f_{t,d}}{f_{t,d} + k \cdot \left( 1 - b + b \frac{l(d)}{avgdl} \right)}
$$
为了方便快速理解，我们可以把公式拆为左半部分和右半部分：

- Bm25(d)：表示给当前这篇文章打出来的**总相关性得分**。

- **log 求和符号**：把用户搜索的话拆成单个词。比如你搜“手机 推荐”，它会把“手机”计算一次，“推荐”计算一次，最后**加在一起**。

- **逆文档频率计算（左半部分）**：负责算“这个词有多罕见”，罕见度得分（IDF：逆文档频率）。

  - **N**：语料库中的总文档数。
  - **dft**：包含当前搜索词 t 的文档总数（Document Frequency）。
  - **加 1 机制（工程落地的防线）**：注意看括号里开头的那个 "1+"。在最原始的 BM25 理论公式中，如果一个词太常见（在超过一半的文档中都出现），算出来的 IDF 可能会变成负数 。，Lucene 为了避免出现负分，巧妙地在公式内部加了 1，**确保了 IDF 得分永远不低于 0** 。

- **词频和长度归一化（右半部分）**：负责算“文章里出现了几次，以及文章长不长”，词频长度得分（TF + 长度惩罚）。
- **$f_{t,d}$**：搜索词 t 在当前文档 d 中出现的频率。

- **$k$（或称 $k_1$）**：控制词频饱和度的核心参数 。分母中 $f_{t,d} + k$ 的存在，使得无论分子的词频 $f_{t,d}$ 有多大，这部分的分值最终都会逼近一个上限，有效防止了“关键词堆砌” 。

- **$b$**：控制字段长度归一化程度的核心参数，取值范围是 $[0,1]$。$b=0$ 时不考虑长度，$b=1$ 时完全按照字段长度与平均字段长度的比值进行归一化。

- **$\frac{l(d)}{avgdl}$**：$l(d)$ 是当前字段的长度，$avgdl$ 是语料库中该字段的平均长度。长度影响是连续的：短于平均长度时得分相对提高，等于平均长度时处于基准状态，长于平均长度时得分逐渐降低。

## BM25 跟 TFIDF 的核心区别及场景差异

这两种算法的核心区别，可以浓缩为**两个参数带来的机制改变**：词频饱和度（参数 k_1）和相对长度归一化（参数 b）。

| **对比维度**         | **TFIDF 算法**                                               | **BM25 算法**                                                |
| -------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **词频 (TF) 的影响** | **无上限增长**。词频越高，得分无限增加。                     | **有饱和上限（Saturation）**。词频达到一定程度后，得分趋于平缓（由参数 k_1控制） 。 |
| **文档长度的考量**   | **绝对长度惩罚**。只要文档长，得分就被压制，极短字段自动获得高权重 。 | **相对长度对比**。将当前长度除以“语料库平均长度”，只有明显长于平均值的文档才会受重罚（由参数 b 控制） 。 |
| **防作弊能力**       | 较弱，容易被“关键词堆砌”攻破。                               | 较强，重复堆砌同一个词带来的得分收益微乎其微 。              |
| **可调优性**         | 基本是“一招鲜吃遍天（One size fits most）”，难以调参 。      | 提供了 k_1 和 b 两个主要参数，可以根据具体业务数据微调 。    |
