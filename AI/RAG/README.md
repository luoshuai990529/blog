# RAG 技术链路与专题索引

这个目录沉淀 RAG 工程链路中的专题学习笔记。

目录表示文章主要解决的问题，Frontmatter 中的 `stage` 和 `tags` 用于表达跨阶段关联。比如长文档分层检索物理上归入“文档处理与知识组织”，但仍可通过 `检索`、`长文档` 等标签被检索到。

## 一、目录结构

```text
RAG/
├── 00-概览与架构
├── 01-文档处理与知识组织
├── 02-查询与检索
├── 03-结果增强与生成可信
└── 04-评测、观测与性能优化
```

## 三、标签与阶段规范

每篇文章保留 `AI`、`RAG` 等主题标签，并使用一个 `stage` 字段标记其主要阶段：

| `stage` | 含义 |
| --- | --- |
| `architecture` | 全局架构与学习路线 |
| `document-processing` | 文档、图片、OCR、表格解析 |
| `knowledge-organization` | 预处理、切片、术语、层级知识组织 |
| `query-understanding` | Query 改写、拆解、过滤条件提取 |
| `retrieval` | 检索模型、索引与混合召回 |
| `ranking` | 融合、去重、过滤与重排序 |
| `generation-governance` | 事实验证、引用、溯源与可信生成 |
| `evaluation` | 离线评测、参数调优与效果验证 |
| `performance-optimization` | 延迟、吞吐、内存与索引成本优化 |

## 五、维护规则

- 新文章按其**主要解决的问题**放入一个目录，不重复保存到多个目录。
- 跨阶段能力通过 `tags` 表达；一个文章只保留一个 `stage`。
- 新增文章时同步更新本 README 的分类入口和推荐阅读顺序。
- 文章间需要补充关联时，使用相对链接，不依赖目录外的重复索引。
